Arena management system

One arena. Six partners. Separate books.

A management system for a cockfighting arena run as an equal partnership. Every partner records their own events, fights, revenue and expenses, sees their own profit and loss, and cannot see anyone else's. Built as a plain Flask app with SQLite: no framework, no build step, no JavaScript bundle.

What it does

Built around how the arena actually runs

Six partners share one physical arena but keep their books apart. Assistants do the data entry, partners approve it, and nobody sees another partner's money.

1Separate books

Every record is owned by the partner who created it. Lists, detail pages and the API are all filtered by owner, so one partner's dashboard never contains another's figures.

2Roles

Partners view and approve. Assistants enter data for their own arena and nothing else. Admins manage users. Each role sees only the screens it needs.

3Approval workflow

Events, revenue, expenses and remittances all start as pending and require the partner's approval, so the numbers on the dashboard are ones somebody signed off.

4Profit and loss

Daily, weekly and monthly P&L computed from the underlying records, broken down by revenue source and expense category, with a seven-day trend.

5Live fight tracking

Start a fight, record bets on either side as they come in, watch the Meron/Wala split move, then close it with a winner.

6Staff and shifts

Personnel records, a daily shift roster and per-shift rates, scoped to the arena that owns them.

Security

The isolation is tested, not assumed

A partnership app is only worth using if the partners' books really are separate. An audit in August 2026 found that several were not, and each fix is now held in place by an automated check.

Honest status

This is working software with a tested security boundary, not a finished product. It has not been through a third-party audit or a production deployment. The repository's build summary lists exactly what remains.

How it is built

Deliberately small

Python and SQLite, server-rendered HTML, and Tailwind from a CDN. No build step, no bundler, no client-side framework. It runs with one command and deploys anywhere that runs Python.
